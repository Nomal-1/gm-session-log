# gm-session-log 명세 (v0.1 초안)

대상: Foundry VTT v12.331 / 던전월드 시스템 1.8.2 / GM 전용.
원칙: 세션 중에는 **GM 전용 채팅 한 줄**만 남긴다. 따로 저장하는 기록은 없다. 추출 때 채팅 로그 전체를 읽어서 정리한다.

표기: ✅ 공식 자료로 확인 / 🧪 공개 자료로 확정할 수 없어 5단계 테스트로 확인

---

## 1. 화면 사건 기록

### 1-1. 감지 방법

| 사건 | 감지 방법 | 근거 |
|---|---|---|
| 장면 전환 | `updateScene` Hook에서 `changes.active === true` | ✅ API 문서 hookEvents(updateDocument), BaseScene `active` 필드 |
| 이미지 보여주기 | `ImagePopout.prototype.shareImage`를 감싸서, 원래 함수를 실행한 **뒤** 기록 | ✅ 문서: 이 동작에는 Hook이 없음, `ShareImageConfig`에 `image/title/uuid/users` 있음 · 🧪 액터 초상화의 Show Players도 이 함수를 거치는지 |
| 저널 보여주기 | `Journal.show`(정적 함수)를 감싸서 기록. `showDialog`도 결국 이 함수를 부른다고 보고 테스트로 확인 | ✅ 문서: `show(doc, {force, users})`, doc은 JournalEntry 또는 JournalEntryPage · 🧪 showDialog → show 경유 여부 |
| 저널 권한 변경 | 권한 설정 창은 Hook 없이 저장할 수 있어서(v0.1.0 테스트에서 Hook으로 감지 실패), 저널 문서 클래스의 저장 전(`_preUpdate`)·후(`_onUpdate`)를 감싸 "누가 볼 수 있었나"를 비교하고 **새로 볼 수 있게 된 플레이어**만 기록. 페이지 권한이 "상위 따름(-1)"이면 저널 권한으로 판단 | ✅ 문서: `testUserPermission(user, "OBSERVER")` |
| NPC 토큰 | `createToken`(숨김 아님) + `updateToken`에서 `changes.hidden === false`. 액터 종류가 `npc`인 토큰만 | ✅ hookEvents · 시스템 `template.json` 액터 종류 `character`/`npc` |

공통 규칙
- 사건을 **일으킨 GM의 화면에서만** 메시지를 만든다(Hook의 `userId === game.user.id`이고 `game.user.isGM`인 경우). 그래서 같은 줄이 두 번 생기지 않는다.
- 기본적으로 **기록 중일 때만** 사건을 남긴다(설정으로 "항상"으로 바꿀 수 있음). 세션 준비 중에 장면을 넘겨 보는 일이 기록에 섞이지 않게 하기 위해서다.
- 원래 함수는 항상 그대로 실행된다. 기록하다가 오류가 나도 원래 동작(이미지·저널 보여주기)은 막지 않는다.

### 1-2. 메시지 형식

- 받는 사람: GM 사용자 전원(`whisper: GM 사용자 id 목록`). 소리와 알림은 없다.
- 보이는 내용: `[21:40:12] 저널 공유 → 카락테르만: 백룡 전설 서류`
  - 시각: 한국 시간 HH:MM:SS
  - 대상: 전체면 "전체", 일부면 캐릭터 이름(없으면 사용자 이름)을 쉼표로 이은 뒤 "만"
- 숨은 꼬리표(`flags["gm-session-log"]`), 화면에는 나오지 않는다:

```json
{
  "kind": "event",
  "type": "journal-show",
  "title": "백룡 전설 서류",
  "uuid": "JournalEntry.abc123",
  "img": null,
  "targets": { "all": false, "userIds": ["u1"], "names": ["카락테르"] },
  "journal": {
    "pages": [
      { "id": "p1", "name": "1쪽", "type": "text",
        "html": "<p>…공개된 부분만…</p>",
        "secretsHidden": 2, "secretsRevealed": 1 }
    ],
    "pagesExcluded": 1
  }
}
```

- 저널은 **보여준 순간의 모습**을 꼬리표에 담는다. 담을 때 비밀 블록을 이렇게 처리한다.
  - 공개 처리된 비밀 블록(`section.secret.revealed`): 넣는다.
  - 공개하지 않은 비밀 블록(`section.secret`에 `revealed`가 없음): **여기서 바로 지운다.** 개수만 남긴다.
  - ✅ 근거: 문서 EnrichmentOptions.secrets, "공개되지 않은 비밀 블록은 제거됨".
  - 이렇게 해 두면 세션 후 GM이 저널을 고치거나 공개 상태를 바꿔도 추출 결과는 실제로 보여준 모습 그대로다. 공개하지 않은 내용은 애초에 꼬리표에 들어가지 않는다.
- 어떤 페이지를 담는가
  - 페이지 하나를 보여줌: 그 페이지만.
  - 저널 전체를 보여줌: **모든 페이지**. v0.1.0 테스트에서 "Show Players"는 권한이 없어도, 강제 옵션 없이도 플레이어에게 보여준다는 것을 확인했다. 공개 안 된 비밀 블록은 여전히 뺀다.
  - 권한 변경: 새로 볼 수 있게 된 페이지만.

## 2. 세션 구간 표시

- 위치: 채팅 탭 맨 위에 GM에게만 보이는 막대(`renderChatLog` Hook에서 `game.user.isGM`일 때만 붙임).
  - 기록 전: `[● 기록 시작] [⤓ 추출]`
  - 기록 중: 막대 전체가 빨간색으로 바뀌고 `■ 기록 종료 (레이븐홀트3 · 00:42:10)` 경과 시간을 1초마다 갱신
- 기록 시작: 세션 이름 입력 창 → 비어 있으면 `2026-10-10`처럼 날짜로 → GM 귓속말 `[21:02:05] ● 기록 시작 — 레이븐홀트3`
- 기록 종료: `[23:48:51] ■ 기록 종료 — 레이븐홀트3` → "지금 추출할까요?" 확인 창
- 상태 저장: 월드 설정 `recordingState`(숨김 항목) `{ active, sessionId, name, startedAt }`. 새로고침하거나 재접속해도 유지된다.
- 채팅 명령: `/기록시작 [이름]`, `/기록종료`, `/기록추출`. `chatMessage` Hook에서 GM일 때만 가로챈다. 플레이어가 입력하면 모듈은 아무것도 하지 않는다(Foundry 기본 동작 그대로).
- 시작/종료 메시지 꼬리표: `{ kind: "marker", action: "start" | "end", sessionId, name }`

## 3. 세션 기록 추출

### 3-1. 범위
- `game.messages`에서 시작 표시를 모두 찾아 `sessionId`로 종료 표시와 짝을 짓는다.
- 시작 표시가 1개면 바로 진행한다. 여러 개면 목록 창을 띄운다(최신 것이 기본 선택): `레이븐홀트3 · 10/10 21:02~23:48`
- 종료 표시가 없으면 지금까지를 범위로 한다.
- 범위: 시작 메시지 시각 이상, 종료 메시지 시각 이하(`message.timestamp` 기준).

### 3-2. 진행 표시
GM 화면에 작은 창을 띄운다: `채팅 정리 중… 412줄` → `자료 수집 3 / 12: 비비안의 저택` → `zip 만드는 중…` → `완료 (18.4MB)`

### 3-3. 세션기록.md 예시
```markdown
# 세션 기록: 레이븐홀트3

- 날짜: 2026-10-10 (토)
- 기록: 21:02:05 ~ 23:48:51 (2시간 46분 46초)
- 참가자: GM(노말) / 카락테르(민수) / 에일린(지우)
- 줄 수: 412

## 기록
```
본문은 표 대신 한 줄에 메시지 하나씩, 앞에 `- `를 붙여 쓴다(마크다운 보기 프로그램에서 줄이 합쳐지지 않게). AI가 읽기에는 표보다 줄 형식이 안정적이다.
```
- [21:02:05] (+00:00:00) GM · 기록 시작 — 레이븐홀트3
- [21:14:03] (+00:11:58) GM · 화면 사건 — 장면 전환: 비비안의 저택 응접실 [자료 001](자료/001_장면_비비안의저택응접실.webp)
- [21:15:10] (+00:13:05) 비비안(GM) · 채팅 — 비비안 드 몽포르
- [21:16:02] (+00:13:57) 카락테르(민수) · 다이스 — 베어 넘기기: 2d6+2 = 11 → 10+ 성공
- [21:16:30] (+00:14:25) 카락테르(민수) · 다이스 — 피해: d10+1 = 7
- [21:17:44] (+00:15:39) 에일린(지우) · 다이스 — 2d6+1 = 6 → 6- 실패
- [21:20:01] (+00:17:56) 에일린(지우) · 귓속말 → GM — 비비안 뒤에 뭐가 있어?
- [21:40:12] (+00:38:07) GM · 화면 사건 — 저널 공유 → 카락테르만: 백룡 전설 서류 [자료 003](자료/003_저널_백룡전설서류.md)
```
- 누가: 캐릭터 이름(말한 대상, speaker) + 괄호 안 사용자 이름(`message.author`, ✅ v12 문서).
- 다이스 판정 구간
  - 던전월드 카드: 본문 HTML에서 읽는다. 무브 이름 `.cell__title`, 합계 `data-roll-total`, 구간 `.result.success`/`.partial`/`.failure`를 10+/7-9/6-로 바꾼다. 식은 `.dice-formula`. ✅ 공식 GitHub `dungeonworld@1.8.2` `rolls.js` 171~375행, `chat-move.html` 2·5·11행, `config.js` 23~36행.
  - 구간 클래스가 없는 카드(피해 굴림, 굴림 없는 무브 사용): 식과 합계만, 또는 "무브 사용: 이름".
  - 일반 `/r` 굴림(`message.rolls`): 식에 `2d6`이 있으면 시스템과 같은 기준으로 구간을 붙이고, 없으면 합계만.
- 본문: HTML 태그를 벗긴 순수 텍스트.

### 3-4. 자료 수집
| 사건 | 넣는 파일 |
|---|---|
| 장면 전환 | 장면 배경 이미지(`scene.background.src`, ✅ 문서상 `background`는 TextureData) |
| 이미지 공개 | 공개한 이미지 |
| NPC 토큰 | 토큰 이미지 `NNN_토큰_이름.webp` + 액터 초상화가 다르면 `NNN_초상화_이름.webp` |
| 저널 | `NNN_저널_이름.md`(꼬리표의 공개된 모습을 마크다운으로 바꿈) + 본문 이미지 `NNN_저널_이름_그림1.webp` |

- 중복: 같은 이미지 경로나 같은 저널 내용이면 파일은 1개만 넣고, 보여준 시각은 모두 적는다.
- 이미지: 긴 변 최대 1600px, webp(품질 0.85). 설정에서 "원본 유지"를 고르면 파일 그대로 넣는다. SVG는 항상 원본.
- 동영상 배경(webm/mp4): 용량이 크더라도 **원본 파일 그대로** 넣는다(사용자 결정 2026-09-30). GIF도 움직임을 살리려고 원본으로 넣는다.
- 외부 URL: 받을 수 있으면 넣고, 막히면 자료목록에 URL만 적는다.

```markdown
# 백룡 전설 서류

## 1쪽
옛날 북쪽 산맥에 흰 용이 살았다…

![그림1](003_저널_백룡전설서류_그림1.webp)
```

### 3-6. zip
- 파일 이름: `세션기록_2026-10-10_레이븐홀트3.zip`. 파일 이름에 쓸 수 없는 문자는 뺀다.
- 만드는 방법: **외부 라이브러리 없이** 모듈 안에 짧은 zip 작성 코드(약 80줄, 무압축 방식)를 직접 넣는다. 이미지는 이미 webp로 압축돼 있어 추가 압축의 이득이 작다. 한글 파일 이름은 UTF-8 표시를 켜서 Windows 탐색기에서도 깨지지 않게 한다. 라이선스 문제도 없다.
- 내려받기: GM 브라우저에서 바로 받는다(Blob). 서버에 파일을 쓰지 않는다.
- 설정을 켜면 `세션기록.json`(메시지 원자료)도 함께 넣는다.

## 6. 🧪 공개 자료로 확정할 수 없어 테스트로 확인할 것
1. 액터 초상화의 "Show Players"도 `ImagePopout.shareImage`를 거치는지
2. 저널 `showDialog`가 `Journal.show`를 거치는지, force일 때 권한 없는 페이지도 보이는지
3. GM 귓속말이 플레이어 브라우저에 아예 전달되지 않는지, 아니면 전달은 되고 화면에만 안 나오는지(콘솔로 확인). 화면에는 절대 나오지 않는다.
4. 월드 설정 항목이 플레이어의 설정 창에 보이지 않는지
